### Shared preamble, output validation, injection boundary and write guards
**Priority:** P1
**Found:** v1.6.0.0 CEO plan review

Four findings that all land in the same place, which is why they are one item.

The `## Preamble` bash block is near-identical in all eight `SKILL.md` files, roughly
30 lines each. Three separate fixes need to go into it:

- **Output validation.** Only `jtbd-switch/SKILL.md:245` and `jtbd-patterns/SKILL.md:237`
  run `python3 -c "import yaml..."` on their own output before reporting success.
  `/jtbd-map`, `/jtbd-brief` and `/jtbd-forces` write and declare done.
  `jtbd-pipeline/SKILL.md:178` instructs the model to verify but gives it no command.
  `validate.py` only runs on committed files, so a user gets an unparseable file
  locally alongside a success message.
- **Prompt injection.** No skill tells Claude that transcript content is data rather
  than instructions. Grepping all 1,735 lines for `injection`, `untrusted` or
  `ignore instructions` returns nothing. `/jtbd-pipeline` reads a folder of untrusted
  files while holding `Bash`, `Write`, `Edit` and `Agent`. The realistic case is not an
  attacker: it is a transcript from an outsourced transcription service.
- **Write guards.** The `-2`/`-3` collision rule exists at `jtbd-switch/SKILL.md:236`
  and `jtbd-patterns/SKILL.md:228` and nowhere else, so `/jtbd-map`, `/jtbd-brief` and
  `/jtbd-forces` overwrite silently. No skill defines behavior for empty input or for
  text that is not an interview.

Do the extraction first: a shared script sourced via `${CLAUDE_PLUGIN_ROOT}`, with
`${CLAUDE_PROJECT_DIR}` as the in-repo fallback. Then all three fixes land once instead
of eight times. Add a validator check that the eight preambles stay in step.

Start at `jtbd-switch/SKILL.md` lines 19-50, which is the reference preamble.

v1.6.0.1 added a `${CLAUDE_PLUGIN_ROOT}` probe to `jtbd-demo` and `jtbd-pipeline`, the
only two preambles that resolve a skills root. That is the fix in two places, not the
extraction — it is exactly the duplication this item exists to remove, and the next
skill that needs an asset path will copy it a third time.

### Every documented install path produced skills Claude Code could not see
**Priority:** was P0
**Completed:** v1.6.0.0 (2026-08-30)

`install.sh` cloned the repo to `~/.claude/skills/jtbd/`, putting every `SKILL.md` two
levels below `~/.claude/skills/`. Claude Code discovers personal skills exactly one
level deep. Verified by running the installer against a sandboxed `HOME`: eight
`SKILL.md` files landed, none at a discovery path, and no `~/.claude/commands/` was
created. Independently, all eight wrappers used a bare relative path that resolves only
when the shell's cwd is the repo root, which is the case README explicitly says is not
the use case.

The repo is now a Claude Code plugin. `/plugin marketplace add savvides/jtbd` then
`/plugin install jtbd@jtbd`. Wrappers are anchored with `${CLAUDE_PROJECT_DIR}` and
exist only for working inside this repo. `install.sh` is a pointer at the plugin
commands.


### /jtbd-pipeline staged nothing when pattern analysis was skipped
**Priority:** was P0
**Completed:** v1.5.0.1 (2026-08-30)

`git add` used globs, and with fewer than 3 transcripts `.jtbd/patterns/` never
exists, so the unmatched glob aborted the entire command. Reproduced in bash
(`fatal: pathspec ... did not match`) and zsh (`no matches found`) — zero files
staged either way, while the pipeline still reported success. Users were told their
interview evidence was committed when it was untracked. Now stages directories, and
reports honestly when nothing was staged.
